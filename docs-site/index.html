a machine.

BLACKBOX packs a program together with its runtime, dependencies, interface and permissions into one file — a .blackbox. The recipient runs the file and gets the whole machine. Nothing is installed. Nothing is fetched. The file is the product.

$ sudo apt install ./blackbox_*_amd64.deb ./blackbox-gui_*_amd64.deb

01Install

Every platform, one file

Each release ships the blackbox command-line tool and the blackbox-gui desktop app. Pick the format you use.

# x86_64 — use _arm64.deb on ARM
$ sudo apt install ./blackbox_*_amd64.deb ./blackbox-gui_*_amd64.deb
$ blackbox doctor
$ blackbox-gui          # launches the desktop app

The GUI package also installs a menu entry and icon.

$ tar xzf blackbox-linux-x86_64.tar.gz
$ sudo install -m755 blackbox-linux-x86_64/blackbox     /usr/local/bin/blackbox
$ sudo install -m755 blackbox-linux-x86_64/blackbox-gui /usr/local/bin/blackbox-gui
$ blackbox doctor

macOS (Apple Silicon): first launch may need xattr -d com.apple.quarantine <binary>.

; unzip blackbox-windows-x86_64.zip, then:
> blackbox.exe doctor
> blackbox-gui.exe       ; desktop app
$ cargo build --release                                  # CLI
$ cargo build --release --features gui --bin blackbox-gui # GUI

02Quickstart

Five minutes, start to ship

$ blackbox init hello
$ cd hello
$ blackbox pack                 # -> hello.blackbox
$ blackbox run hello.blackbox   # provisions Python 3.12.7 once, then runs

Send hello.blackbox to a colleague by any means — USB, mail, a file server. They run blackbox run hello.blackbox. Their host Python is never consulted.

03How it works

The file rebuilds the machine

source your project
code + blackbox.yaml
pack →
artifact app.blackbox
one file, hash-addressed
run →
any machine the app
runtime verified, then exec

pack resolves dependencies for the target platform, pins exact versions and hashes into blackbox.lock, lays them out as deterministic layers, and writes a sorted ZIP with a fixed timestamp. Identical source plus lockfile produces a byte-identical package.

run verifies every hash, fetches and verifies the declared interpreter, materialises layers from the shared store, scrubs the environment, enforces the declared permissions, and execs the entrypoint.

No registry

There is no account, no server and no store. A .blackbox is a documented, inspectable archive you can copy, email or archive for a decade.

04In the box

What a package carries

runtime
Python, Node.js, WASM, Rust or a native binary. Provisioned from hash-pinned upstream builds, or compiled at pack time.
dependencies
pip and npm resolved against the target platform, pinned by version and sha256.
permissions
Filesystem, network and process access declared up front. Defaults deny everything. The recipient approves the exact content once.
interface
cli, web or gui, plus named subcommands.
limits
Memory, CPU and process ceilings, enforced where the OS allows and labelled honestly where it does not.
signature
Optional Ed25519 over the content digest. The publisher is pinned by fingerprint.
secrets
Optional X25519 + AES-256-GCM sealing to a recipient, decrypted only at run time.
provenance
Tool version, host triple, target and layer digests, recorded in the package.

Deduplication

Layers live in a content-addressed store under ~/.blackbox/objects/sha256/. Ten apps that use Python 3.12 and NumPy share one copy on disk, while each stays individually portable as a single file.

05Examples

Start from a working appliance

datasift

A CSV cleaning appliance with a web UI. Standard library only — no third-party dependencies at all.

$ cp -r examples/datasift myapp
$ cd myapp && blackbox pack
$ blackbox run datasift.blackbox
# -> http://127.0.0.1:8765

research-repro

A sealed research environment. Pip dependencies pinned by hash; reviewers reproduce the analysis with one command.

$ cp -r examples/research-repro repro
$ cd repro && blackbox pack
$ blackbox run research-repro.blackbox
# -> output/report.html

wordcount-node

Node.js 22 with npm dependencies. The official nodejs.org distribution, pinned by version and sha256.

$ blackbox init wordy --template node
$ cd wordy && blackbox pack
$ blackbox run wordy.blackbox

native

A compiled binary is its own runtime. Cross-compile to any target at pack time.

# blackbox.yaml
runtime:
  type: native
entrypoint:
  command: ./bin/app

07Trust

Sign it or seal it

Ed25519 for provenance, X25519 + AES-256-GCM for secrets and whole-package encryption. No invented cryptography.

$ blackbox keygen lab --publisher "Research Lab X"
$ blackbox sign   pkg.blackbox --key lab
$ blackbox trust  lab.pub.pem --publisher "Research Lab X"
$ blackbox verify pkg.blackbox
# -> Signature: VALID - trusted publisher

Seal secrets to a recipient, or encrypt the whole package:

$ blackbox seal    pkg.blackbox --secrets .env --to lab.seal.pub.pem
$ blackbox encrypt pkg.blackbox --to lab.seal.pub.pem

Before the first run of an unsigned package you are shown exactly what it asks for — filesystem, network, process — and you approve or decline. Approvals are remembered per content digest. A package whose contents changed after signing will not run.

08Format

An archive you can read

A .blackbox is a deterministic ZIP. Every field is fixed, so the same inputs always produce the same bytes.

MemberPurpose
manifest.jsonCanonical JSON of the normalised manifest.
blackbox.lockExact versions, URLs and sha256 of dependencies and runtime.
application.tar.zstYour code and assets, content-addressed.
dependencies.tar.zstResolved dependency layer, per target.
layers.jsonLayer index: kind, target, digest, exec flags.
checksums.jsonsha256 of every other member — the integrity root.
signature.jsonOptional Ed25519 signature.
encrypted.jsonOptional whole-package encryption.
provenance.jsonBuild metadata.

Manifest

The contract between creator and runtime. Validation is strict: unknown fields fail at pack time, not mysteriously at run time.

format_version: "1"
name: "my-app"
version: "1.0.0"
publisher: "Your Name"

runtime:
  type: "python"        # python | node | native | wasm | rust
  version: "3.12"
  target: "x86_64-unknown-linux-gnu"

entrypoint:
  command: "python"
  args: ["main.py"]

permissions:
  filesystem:
    read:  ["./input"]
    write: ["./output"]
  network:
    enabled: true
    allow: ["api.example.com"]
  process:
    spawn: false

interface:
  type: "web"
  port: 8765
09Desktop

A window for the whole workflow

blackbox-gui is an egui desktop app: manage projects, edit the manifest as a form or as raw YAML, and pack or run without leaving the window. It calls the same library functions as the CLI, so packages it produces are byte-identical to blackbox pack.

projects
Create from templates, filter, open folders, remove.
manifest
Visual form or raw YAML with inline validation and Ctrl+S.
pack
Output path, target triple, thin mode, watch mode.
run
Work directory, input files, entrypoint, --yes, --data, --log.
log
Captured stdout and stderr with filters and auto-scroll.
settings
Theme, projects directory, default target, mirror URLs.
$ cargo build --release --features gui --bin blackbox-gui
$ ./target/release/blackbox-gui
